# Voice conversation: running it (delivery, text mode, report)

How a conversation written with `references/voice.md` (§ 1, § 1b) reaches the learner, how its report comes back and what to do with it. Sections keep their numbers: § 2 voice mode, § 3 text mode, § 4 afterwards.

## Which way (check in this order, every time you send a conversation)

| # | Situation | The conversation reaches the page | The report comes back |
| --- | --- | --- | --- |
| 1 | No consent, no Gemini key, or the voice page failed | **Text mode** (§ 3): you play the other person in chat | You write it |
| 2 | The Google Drive connector is available **and** the learner's Drive has the voice folder | **Google Drive** (§ 2, preferred): save the code in `voice-briefs`, give `drive_link` | You read it from `voice-reports` |
| 3 | The learner's *English course* folder on their computer is connected to this session (and `voice_page_url` is empty) | Save the code file in the folder; the page opens it | You read it from the folder |
| 4 | iPhone / iPad without Drive | Give `link` (the conversation travels in the link) | The learner shares or copies it into the chat |
| 5 | Anything else | Give `code` in a code block; the learner pastes it | The learner attaches the downloaded file |

`engine.py voice-code --brief brief.json` returns `code` (starts with `EC2-`), and, when `voice_page_url` is set, `drive_link` (page address + `#<session_id>`, for way 2) and `link` (page address + `#` + the code, for way 4).

## 2. Voice mode (the learner gave consent and has a Gemini key)

**Where the page is.** When `config.json` has `voice_page_url`, the voice page is that web address, on a computer and on a phone: give that address and never send, save or copy the page file to the learner (no `english-voice.html` in their folder). Only when `voice_page_url` is empty is it a local file on the learner's computer (`voice-page/index.html`, opened with a double click in Chrome or Edge). It talks directly to Gemini Live with the learner's **own free API key**, which stays in their browser. There is no server: the brief travels inside the conversation code and the report comes back as a file the learner attaches.

**Google Drive (preferred when set up: any device, no folder, no long links).** Check it FIRST, before any other way, every time you send a conversation. Use it when the Google Drive connector is available in this session and the learner's Drive has the folder named in `config.json` › `voice_drive_folder` (find it: `search_files` with `title = 'English course (voice)' and mimeType = 'application/vnd.google-apps.folder'`; its subfolders `voice-briefs` and `voice-reports`: `search_files` with `parentId = '<folder id>'`). The page reaches that folder through the learner's Apps Script bridge (`voice-page/drive-bridge.gs`, set up once by the owner of the Drive: § First time). In Drive mode skip the computer-folder and link steps: save the code to Drive (step 2), give the page address that ends in the session number (`drive_link`), and read the report from Drive (step 3).

**iPhone / iPad.** The same page works in Safari (iOS/iPadOS 16.4 or later), but only from a web address (https), never as a file. It is used only when `config.json` has `voice_page_url` (the owner's published copy of the page). Ask once which device the learner uses for the voice calls and write it in the session note. On iPhone/iPad there is no folder: skip the folder steps below, give the **link** (step 2) and get the report from the chat (step 3). If `voice_page_url` is empty, an iPhone/iPad learner uses a computer for the voice calls or text mode (§ 3).

1. **First time only.**
   - **Google Drive bridge** (once per learner, only if they want Drive mode): the learner creates the folder (or you create it with `create_file`, mimeType `application/vnd.google-apps.folder`, plus `voice-briefs` and `voice-reports` inside), then follows the steps at the top of `voice-page/drive-bridge.gs` (send them the file with SendUserFile, with the folder id written in `ROOT_ID`): new Apps Script project, paste, Deploy › Web app (Execute as: Me · Who has access: Anyone), authorize, run `connectionCode()`. A learner whose script is older than bridge version 2 (the page says the conversation "is not the one Google Drive gives") updates it once with the steps at the top of that file; the address and the key do not change. In the voice page, on every device, they press **Connect Google Drive** and paste that line — **in the page, never in the chat** (it works like a password for that folder; if it is shared, they run `newKey()` and paste the new line).
   - **iPhone / iPad:** they open the link of their first conversation in **Safari** (not inside another app). The page asks for the Gemini key (as below) and Safari asks for the microphone once. Tell them: headphones help, keep the screen on the page until the end (switching apps stops the call), and if there is no sound, turn the volume up.
   - **The English course folder** (computer). Ask the learner to make a folder called *English course* on their computer. If this session can reach their computer (the remote-devices tools are present and that folder is connected), save the page into it as `english-voice.html` (SendUserFile, then `device_commit_files`); otherwise send `voice-page/index.html` with SendUserFile and ask them to save it there as `english-voice.html`. They open it with a double click in Chrome or Edge.
   - In the page they press **Choose my English course folder** and pick that folder (Chrome/Edge ask once for permission). From then on, every report is saved in `English course/voice-reports/`. If they skip this, the page downloads the report instead.
   - The page asks for a Gemini key. Guide them step by step (simple English, one Spanish sentence if needed): open **aistudio.google.com/apikey**, sign in with a Google account, click **Create API key**, copy it and paste it **in the page, never in the chat**. It is free; no card is needed. If they paste a key in the chat, tell them not to share it and to delete it and create a new one in AI Studio.
   - Have them press *Test my microphone*.
   - If they cannot or do not want to create a key, use text mode (§ 3).
2. **Conversation code.** `engine.py voice-code --brief brief.json` → `code` (starts with `EC2-`).
   - **Google Drive mode** (preferred): `create_file` in `voice-briefs` with `title` `conversation-<session_id>.txt`, `textContent` = the code alone, `contentMimeType` `text/plain`, `disableConversionToGoogleType` true. Give `drive_link` alone on its own line (not in a code block, so it can be tapped): the page asks the bridge for exactly that conversation, so whatever else is in the folder (old, abandoned or test conversations) does not matter. **Never move, rename or trash files in the learner's Drive for this.** If the page says the conversation is not in Drive yet, wait a moment and have the learner press **Open my next conversation**. If it says the conversation "is not the one Google Drive gives" (an old bridge script) or that Drive did not answer, give the `link` or the code as below.
   - **English course folder connected to this session** (only when `voice_page_url` is empty; nothing to paste): write the code alone in a text file and save it as `English course/voice-briefs/conversation-<session_id>.txt` (Write it under the outputs folder, then `device_commit_files`). The page opens the newest conversation without a report by itself, or when the learner presses **Open my next conversation**. Tell them: open the voice page (reload it if it is already open), press *Open my next conversation* if the situation does not appear, then *Start*.
   - **iPhone / iPad**: `voice-code` also returns `link` (when `voice_page_url` is set). Give the link alone on its own line (not in a code block, so it can be tapped); it opens Safari with the conversation ready. If the link does not open, give the code in a code block to paste.
   - **Otherwise**: give the code on its own line in a code block; the learner pastes it and presses *Continue*.

   Then tell them in English how the call works: press *Start*; the other person says hello first; to speak, press **My turn to speak** (or the space bar), and when they finish, press **I'm done** (the other person waits until then); when the page says it has finished, come back here and type **done**.
3. **Getting the report** (`voice-report-<session_id>.json`):
   - **Google Drive mode:** `search_files` with `parentId = '<voice-reports id>' and title = 'voice-report-<session_id>.json'`, then `download_file_content` (base64 → decode the JSON). If it is not there yet, wait a moment and look again (max. 3 times); then ask the learner what the page said (if Drive failed, the page falls back to download, share or copy).
   - If the English course folder is connected to this session: list `English course/voice-reports/` (`device_list_dir`), stage that file (`device_stage_files`) and read it. If it is not there yet, wait a moment and look again (max. 3 times).
   - Otherwise (or if it is not in the folder): ask the learner to **attach** the downloaded file to the chat (the page also has *Copy the report*, to paste it).
   - **iPhone / iPad:** the page does not download. The learner taps *Share the report with Claude* (when the phone offers it) or *Copy the report* and pastes it in the chat. Read the pasted JSON exactly as it is and save it as below.
   - Gemini only writes the **pronunciation notes** (it is the only one that heard the audio). The page leaves `target_grammar_uses`, `priority_vocabulary_used` and `errors` empty and every `objectives_met` as `false`.
   - **Practice:** fill those four fields yourself from the transcript before saving (§ 4). **Exam:** leave them as they are; the evaluator works from the transcript.
   - Save it as `voice-sessions/<session_id>/report.json` in the project and validate it (`voice_report`). Check that `session_id` and `mode` match the brief. For an exam, copy its `channel` (`voice` or `text`) into `speaking.channel` of the evidence package: the engine accepts a Speaking score without the pronunciation row only in text mode. If `end_reason` is `quota_exceeded` or `technical_error`: in practice, continue in text mode; in the exam, offer to repeat the Speaking in voice mode later or in text mode now (the learner chooses).
   - **Exam: check the agent before scoring** (P04, owner decision 2026-10-27). Read the agent's turns. If the agent **malfunctioned** — text that has nothing to do with the situation (e.g. a paragraph about technology in the middle of a family photo), leaving the role, or helping/correcting the learner (repeating their sentence corrected, giving words, "Correct!") — the Speaking attempt is **void**: do not send it to the evaluator and do not score the event yet. Tell the learner briefly that the agent made a mistake and that this attempt does not count, and run a new Speaking (new situation, same rules) before scoring. Keep the void report in the project with `void_reason` in your notes.

If the page says the microphone is blocked: the learner clicks the lock/camera icon in the address bar, allows the microphone and tries again (iPhone/iPad: Settings › Apps › Safari › Microphone › Allow, then reload); if it still fails, use text mode. If it says Gemini did not accept the key, the learner pastes a new key in the page.

## 3. Text mode (no voice page, no consent, or as a fallback)

You play the other person in chat, following the brief exactly:

- Show only the situation, then the title and the text of `shared_text` (in practice and exam), and talk only about it. Never reveal the hidden objectives.
- Speak as the character, within the grammar ceiling and the level; short sentences at A1–A2.
- Make it a real conversation, not a quiz: open questions by default (what, where, why, how, tell me about…), follow-ups on the learner's own answers, short opinions of your own, topics from the learner's life and interests. Use a closed question only when the target grammar needs it, and follow it with an open one.
- Practice: correct directly ("We say: …" + the correct phrase), one mistake per message, then continue the conversation.
- Exam: no corrections, hints or help (do not repeat the learner's sentence corrected, do not say "Correct!"); end after the target learner turns of the level (`voice.md` § 1, exam: A1 8 · A2 10 · B1 12 · B2 14 · C1 16; placement Speaking: 6), with a short goodbye.
- When it ends, write the `voice_report` yourself with `channel: "text"`, the literal chat transcript, `pronunciation_notes: []`, `duration_s: 0`, `audio_deleted_at` = `ended_at`. In **practice**, add target-grammar uses, vocabulary used, errors and objectives met. In the **exam**, leave `target_grammar_uses`, `priority_vocabulary_used` and `errors` empty and set every `objectives_met` to `false`: your judgement must not reach the evaluator; it works only from the transcript. Save it as `voice-sessions/<session_id>/report.json`.

In text mode pronunciation cannot be assessed: the evaluator omits that criterion. Write `"channel": "text"` in `speaking` of the evidence package too, so the engine accepts the Speaking score without that row.

## 4. Afterwards

- Practice — analyse the transcript (learner turns only; never count the agent's words) and fill the report:
  - `target_grammar_uses`: every complete attempt at the target grammar, `{"turn", "form", "accurate"}` (+ `correction_given` if the agent recast it);
  - `priority_vocabulary_used`: entries of the brief's list the learner said, in the taught sense;
  - `errors`: every learner error `{"turn", "learner_said", "issue", "section"}` (+ `recast`), including word order (*"Paris is in France?"* for *"Is Paris in France?"*);
  - `objectives_met`: `true` only for objectives the learner did personally, with the target forms.
  Then add it to the learner's memory — `engine.py practice-log --state STATE --lesson <lesson> --report report.json` (every error that has a `section` is counted in `errors.json`; a session is added only once) — and comment on 2–3 points (what went well, one recurring error with its correct form, one pronunciation point). For pronunciation, the main evidence is the **pronunciation check** in the transcript (the learner's attempt and Gemini's comment right after it); Gemini's notes are often incomplete. Ignore a note that only names a different word ("pronounced T-shirt as teacher", "how many for how much"): that is usually speech recognition or word choice, not pronunciation.
- The transcript comes from automatic speech recognition. A learner line that is garbled or looks like Spanish where an English answer was expected (e.g. *"y así"* for *"Yes, it is"*) is a recognition problem, not the learner's error: do not correct it as grammar. Words that sound the same are written by the recognizer in one way only (*whose* / *who's*, *their* / *there*, *its* / *it's*): decide from the words around them (*"Who's baby is this?"* is a correct *whose*), and never mark them as errors on spelling alone.
- Exam: do not comment on anything until you have the engine's decision.
